# 独立レビュー結果

対象：Suno Downloader Web v0.1.0。React＋Tailwind CSS画面、Python API、ジョブ制御、既存取得処理の接続、Docker／Render設定を独立した別エージェントが確認した。

## 判定

**CONDITIONAL PASS（確認したローカル実装・自動テストの範囲）**。検出したHigh指摘は修正・再検証済み。Suno実接続、Render本番配置、スマホ実機についての合格を意味しない。

## 指摘と修正確認

| ID | 重大度 | 内容 | 対応・再検証 |
| --- | --- | --- | --- |
| R1 | High | 子プロセス終了より先に完了イベントを受信すると、実行ループが結果を破棄し、正常ファイルを失敗扱いで削除する | 最新の結果を全イベント処理間で保持。完了イベント送信後0.4秒稼働する実子プロセスによる回帰テスト成功 |
| R2 | High | StrictModeによる初期化の二重実行でセッションCookieとCSRFトークンが食い違う可能性 | セッション初期化Promiseを共有。並行初期化の通信1回・初期化失敗後再試行のテスト成功 |
| R3 | High | RenderのHTTPS Originと内部HTTPのbase_urlが異なり、正常操作を拒否する可能性 | PUBLIC_ORIGIN／RENDER_EXTERNAL_URLを正本として検証。内部HTTP＋外部HTTPS Originのテスト成功 |
| R4 | Medium | 入力長判定がContent-Lengthだけに依存し、未指定／分割転送を制限できない。不正な値で500になる | 実受信バイト制限と不正ヘッダー400を追加。分割転送6000バイト413・不正値400を確認 |
| R5 | Medium | ファイル取得時の所有者確認と利用中カウント加算の間に、期限切れ清掃が競合し得る | 同一ロック内でファイル利用権を確保する実装を確認 |
| R6 | Medium | 一時的な復元通信失敗でもジョブIDを削除し、再接続できなくなる | 404／401の場合だけ失効として扱う修正を確認 |
| R7 | Low | 元音源検証が出力準備として表示され、変換工程で表示順が逆戻りする | 元音源検証を処理工程、出力検証を保存準備工程に分類する修正を確認 |

## 独立実行した検証

- `python -m pytest backend/tests -q`：**6 passed**。
- `npm run typecheck`：成功。
- `npm run lint`：成功。
- `npm test`：**6 passed**。
- `npm run build`：成功。ReactとTailwind CSSの生成物を確認。

バックエンド検証には、セッション・CSRF・不正URL・所有者分離・保存ファイル取得・期限切れ・処理中の追加拒否・キャンセル、実子プロセスの完了通知順序、Render Origin、入力サイズを含む。暗号処理や変換の検証はテスト用データを用い、Sunoからの実取得成功とは区別している。

## 未検証・残存制約

- 実際のSunoサービスに対する音源取得・権利応答・復号の互換性は別途実接続確認が必要。既存エンドポイント・CDNパスは将来変更され得る。
- Renderへの実配置、無料枠での速度・長時間動作、外部通信到達性は未検証。
- WindowsおよびAndroid／iOSの実機操作・端末の保存先表示は未検証。
- API状態・CSRF秘密値・一時ファイルはプロセス単位のため、1ワーカー前提。サーバー再起動後は再実行が必要。
- ブラウザQA結果は統括担当の検証記録を参照。本レビュー担当はブラウザを操作していない。
